Topic 3: Methodology

Methodologies

Software engineering methodologies are important for creating better software projects. It helps developers plan, produce, and test software. These methods simplify tasks, improve collaboration, and achieve timely and budget-friendly outcomes.

Waterfall Model

The waterfall model is the classic process, it is one of the first model to be introduce. It is widely known, understood and used. In some respect, waterfall is the ”common sense” approach.

When to use Waterfall?

Waterfall is used when projects which not focus on changing the requirements, small project and the requirement of the project is well understood by customer, no ambigoues requirements.


Advantage

  • Simple and easy to use

  • Phases are clear

  • Suitable for small project

  • Easy to manage


Disadvantage

  • Does not allow much revision

  • Not suitable for complex system

  • High risk and uncertainty

  • No feedback path

Prototyping

A sample, model or release of a product built to test process to be replicated, the goal of prototyping is to evaluate an idea. It is iterative, trial and error process that takes place between developers and the users

When to use Prototype?

Prototype should be used when the desired system needs to have a lot of interaction with the end users. For example, Online systems, web interfaces have a very high amount of interaction with end users, are best suited for Prototype model



Advantage

  • Active involvement

  • Easy detection of missing functionality

  • Quick Feedback

  • Flexibility



Disadvantage

  • Time-consuming

  • Poor decision-making

  • High upfront cost

  • Misconception

Boehm's Spiral Model

Process is represented as a spiral rather than as a sequence of activities with backtracking.Each loop in the spiral represents a phase in the process. No fixed phases such as specification or design - loops in the spiral are chosen depending on what is required.

When to use Spiral?

When have large applications and systems which will be built-in small phases or segments and there is a budget constraint and risk evaluation is important.



Advantage

  • Good for large project

  • Strong documentation control

  • Have risk analysis

  • Flexibility



Disadvantage

  • Costly

  • Requrie risk analysis expertise

  • Not suitable for small project

  • Risk phase dependent

Rational Unified Process

A modern generic process derived from the work on the UML and associated process. Brings together aspects of the 3 generic process models discussed previously.

When to use RUP?

RUP is well-suited for large-scale, complex projects that require rigorous planning, design, and documentation. If your project can benefit from iterative development, where the software is built and refined over multiple cycles, RUP provides a framework that supports iterative and incremental development, enabling continuous feedback and improvement.





Advantage

  • Well structured

  • Strong documentation control

  • Ireative development

  • Flexibility





Disadvantage

  • Complexity

  • Resource intensive

Rapid Application Development

Object-oriented approach to systems development that includes a method of development as well as software tools. It enable software to be developed in a shorter time frame and sometimes with a higher quality.

When to use RAD?

Have the team includes programmers and analysts who are experienced with it. Needed to complete development in extremely short of time.



Advantage

  • Quick initial reviews

  • Measureable progress

  • Reduced development time



Disadvantage

  • Loosely documentation

  • Requrie skilled expertise

  • Complex management
