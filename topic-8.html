Topic 8: Implementation and Testing

Coding Standards

Code not only needs to do its job well, but must also be easy to add to, maintain and debug. Needing to make changes to code could require a lot of energy to decipher lines of code that doesn’t make its purpose or intentions clear. Neatly commented with details that explain any complicated constructs and the reasoning behind them.

Why need coding standards

By following coding standards, it helps to make ur code have consistent look, imporve the readability, simplifies copying, editing, and maintance, and company wide standaziations.

Principle of Good Coding

1. KISS - Keep It Short and Simple
2. DRY - Don't Repeat Yourself
3. Abstraction - Each significant piece of functionality in a program should be implemented in just one place in the source code
4. Open/Closed Principle - Software entities should be open for extension, but closed for modification.
5. Maximize Coupling - Minimize the dependencies on other areas of code
6. Maximize Cohension - Similar functionality should be in same components



Code Smells

Code smells is any characteristic in the source code of a program that possibly indicates a deeper problem.
1. Duplicated Code
2. Large Classes
3. Long Methods
4. Long Parameter List

Refactoring

Improve your software internal structure in a safe way while not changing / adding / removing behavior or external interfaces. +readable code, +simplified code, +easier to change, +easier to add new value, +reduced redundancy, advices how to go on to keep-improve software, and last but not least +automatic tests.

Software Testing

Testing is the process of exercising a program with the specific intent of finding errors prior to delivery to the end user. Each program must tested to make sure it functions correctly. For example, Desk checking : the process of reviewing the program code to spot logic errors, which produce incorrect result

Type of Testing

Unit Testing

- The testing of an individual program or modul.
- Objective is to identify and eliminate execution errors that could cause the program to terminate abnormally, and logic errors that could have been missed during desk checking




System Testing

- Verify that all system components are integrated properly and that actual processing situations will be handled correctly
- Confirm that the information system can handle predicted volumes of data in a timely and efficient manner




Integration Testing

- Testing two or more programs that depend on each other to make sure that the programs work together properly






Test Plan

Test plan is a type of document to have all testing script such as testing steps, expected and actual result, remarks and test case.

  • Used as a guide to test software

  • Uses ‘dummy data’ (sample data)

  • Usually prepared before software is built

  • Prepared by ‘software testers’
